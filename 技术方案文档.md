## 二、核心技术栈

### 2.1 前端（三端统一）

| 层面 | 技术选型 | 说明 |
|------|---------|------|
| **跨平台框架** | Expo SDK 52+ (React Native) | 一套代码 → iOS / Android / Web(H5)，Expo Router 文件路由 |
| **路由** | Expo Router v4 | 文件系统路由，三端统一 URL，支持 Deep Link |
| **样式方案** | NativeWind v5 + TailwindCSS v4 | H5 端原生 Tailwind，Native 端通过 NativeWind 桥接，class 写法统一 |
| **状态管理** | Zustand + React Query (TanStack Query) | Zustand 管理客户端状态，React Query 管理服务端状态与缓存 |
| **API 通信** | tRPC v11 | 端到端类型安全，前后端共享类型，零 schema 冗余 |
| **表单** | React Hook Form + Zod | Zod schema 前后端共享（放在 `packages/shared`） |
| **动画** | React Native Reanimated 3 | 卡片滑动、匹配动效、过渡动画 |
| **手势** | React Native Gesture Handler | 左右滑动匹配核心交互 |
| **图片** | Expo Image | 高性能图片加载、缓存、渐进加载 |
| **视频播放** | Expo Video | 个人资料短视频播放 |
| **推送** | Expo Notifications + FCM/APNs | 统一推送方案 |
| **地图** | react-native-maps + H5 高德 SDK | 活动地点展示、约会位置共享 |

### 2.2 后端

| 层面 | 技术选型 | 说明 |
|------|---------|------|
| **API 框架** | NestJS v11 + tRPC Adapter | TypeScript 全栈，模块化架构 |
| **数据库** | PostgreSQL 16 | 用户数据、关系数据，PostGIS 扩展支持地理位置 |
| **ORM** | Prisma v6 | 类型安全 ORM，迁移管理，schema 与 tRPC 无缝配合 |
| **缓存** | Redis 7 (Dragonfly 兼容) | 会话管理、在线状态、推荐缓存、限流 |
| **搜索** | Meilisearch | 用户搜索、筛选，轻量替代 ES，部署简单 |
| **消息队列** | BullMQ (Redis-based) | 异步任务：推送、审核、匹配计算、邮件 |
| **对象存储** | 阿里云 OSS / AWS S3 | 照片、视频、语音消息 |
| **CDN** | 阿里云 CDN / CloudFront | 静态资源加速 |

### 2.3 实时通信

| 功能 | 技术选型 | 说明 |
|------|---------|------|
| **IM 聊天** | Socket.IO v4 (独立服务) | 双向实时消息，支持断线重连、消息确认 |
| **消息持久化** | PostgreSQL + Redis Stream | PG 存历史消息，Redis Stream 做消息投递队列 |
| **音视频通话** | WebRTC + 自建信令服务 | P2P 优先，TURN 服务兜底 NAT 穿透 |
| **TURN/STUN** | coturn | 开源 TURN 服务器，保障复杂网络下的通话质量 |
| **视频相亲大厅** | LiveKit (开源) | 多人音视频房间，支持红娘主持模式 |

### 2.4 AI / 算法服务

| 功能 | 技术选型 | 说明 |
|------|---------|------|
| **推荐引擎** | Python FastAPI + Redis | 协同过滤 + 向量相似度，实时特征更新 |
| **向量数据库** | pgvector (PG 扩展) | 用户画像向量化存储与 ANN 检索，无需额外部署 |
| **内容审核** | Python FastAPI | 接入阿里云/腾讯云内容安全 API + 自训练敏感词模型 |
| **AI 破冰** | Claude API / 通义千问 API | 基于双方资料生成开场白建议 |
| **人脸活体检测** | 阿里云金融级实人认证 | L3 真人认证，活体检测 + 公安库比对 |

### 2.5 DevOps & 基础设施

| 层面 | 技术选型 | 说明 |
|------|---------|------|
| **容器化** | Docker + Docker Compose (开发) | 本地一键启动全套服务 |
| **编排** | Kubernetes (生产) / 阿里云 ACK | 微服务编排、自动扩缩容 |
| **CI/CD** | GitHub Actions | Turborepo 智能缓存 + 按变更范围触发构建 |
| **监控** | Grafana + Prometheus + Loki | 指标监控 + 日志聚合 |
| **APM** | Sentry | 前端异常监控 + 后端错误追踪 |
| **H5 部署** | Vercel / 阿里云 OSS + CDN | Expo Web 导出静态部署 |
| **App 分发** | EAS Build + EAS Submit | Expo 官方云构建，直接提交 App Store / Google Play |

## 四、关键架构设计

### 4.1 三端统一方案：Expo Universal App

```
                    ┌──────────────────┐
                    │   Expo Router    │
                    │  (文件系统路由)   │
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
         ┌────────┐    ┌────────┐    ┌────────┐
         │  iOS   │    │Android │    │ Web/H5 │
         │ (原生)  │    │ (原生)  │    │(React) │
         └────────┘    └────────┘    └────────┘
              │              │              │
              └──────────────┼──────────────┘
                             │
                    ┌────────┴────────┐
                    │  NativeWind v5  │
                    │ (Tailwind 统一)  │
                    └─────────────────┘
```

**为什么选 Expo 而非 React + React Native 分仓：**

| 对比 | Expo Universal App | React(H5) + React Native(分仓) |
|------|-------------------|-------------------------------|
| 代码复用率 | **90%+**（路由/组件/逻辑全共享） | 40-60%（仅逻辑层可共享） |
| 路由方案 | Expo Router 三端统一 | 两套路由系统需分别维护 |
| 样式方案 | NativeWind 统一 className | Tailwind(H5) vs StyleSheet(RN) 两套 |
| 构建部署 | EAS Build 一站式 | H5 和 Native 分别配置 |
| 维护成本 | **低** | 高（两套代码需同步迭代） |

**平台差异处理策略：**

```typescript
// 使用 Platform 模块处理平台差异

// 方式 1：Platform.select

// 方式 2：文件后缀约定 (Expo 自动解析)
// SwipeCard.tsx        → 默认实现 (Native)
// SwipeCard.web.tsx    → H5 专用实现
```

### 4.2 端到端类型安全（tRPC 链路）

```
packages/shared/          →  Zod Schema 定义
        │                     (register.schema.ts)
        ▼
apps/server/trpc/         →  Router 引用 Schema 做入参校验
        │                     自动推导返回类型
        ▼
packages/api-client/      →  tRPC Client 自动获得完整类型
        │                     封装为 React Query hooks
        ▼
apps/mobile/              →  直接调用 hooks，全链路类型安全
apps/web-admin/               无需手写任何 API 类型
```

```
┌──────────┐     WebSocket      ┌────────────────┐
│  Client  │◄──────────────────►│  Chat Service  │
│ (移动/H5) │    Socket.IO       │  (Node.js)     │
└──────────┘                    └───────┬────────┘
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
              ┌──────────┐       ┌──────────┐       ┌──────────┐
              │  Redis   │       │PostgreSQL│       │ BullMQ   │
              │ Pub/Sub  │       │ 历史消息  │       │ 推送队列  │
              │ + Stream │       │          │       │          │
              └──────────┘       └──────────┘       └──────────┘
```

**消息投递保障：**

```
1. Client → Chat Service：发送消息 + 本地 messageId
2. Chat Service → Redis Stream：写入投递队列
3. Chat Service → PostgreSQL：持久化存储
4. Chat Service → 对方 Client：实时推送 (在线)
         或 → BullMQ → 推送服务：离线推送 (APNs/FCM)
5. 对方 Client → Chat Service：ACK 确认
6. Chat Service → 发送方 Client：已送达/已读回执
```

## 九、性能与安全设计

### 9.1 性能优化

| 策略 | 实施方案 |
|------|---------|
| **图片优化** | OSS 图片处理（裁剪/压缩/WebP），CDN 分发，客户端渐进加载 |
| **列表虚拟化** | FlashList 替代 FlatList，大列表流畅滚动 |
| **API 缓存** | React Query staleTime 策略 + Redis 服务端缓存 |
| **推荐预加载** | 客户端预拉取下一批推荐数据，滑动体验零等待 |
| **数据库索引** | 复合索引覆盖高频查询，pgvector HNSW 索引加速向量检索 |
| **连接池** | Prisma 连接池 + PgBouncer 减少数据库连接开销 |

### 9.2 安全措施

| 层面 | 措施 |
|------|------|
| **认证** | JWT Access Token (15min) + Refresh Token (30d)，HttpOnly Cookie |
| **传输** | 全站 HTTPS，WebSocket 使用 WSS |
| **限流** | NestJS Throttler + Redis 滑动窗口，防暴力破解与爬虫 |
| **输入校验** | Zod schema 前后端双重校验，Prisma 参数化查询防 SQL 注入 |
| **隐私合规** | 手机号脱敏存储，照片 EXIF 信息自动剥离，数据导出/删除接口 |
| **内容安全** | 实时文本/图片审核，敏感词过滤，诈骗话术 AI 检测 |
